**الصف الثاني بكالوريا — مسار الهندسة وعلوم الحاسب (عربي ↔ English)**

يضم هذا القاموس جميع المصطلحات المقررة في الفصول الأربعة الأولى (131 مصطلحًا)، متبوعة بجدول المصطلحات المتشابهة التي تتكرر في أسئلة المقارنة والاختيار من متعدد، وجدول الاختصارات التي تُكتب بالحروف اللاتينية.

## أولًا: المصطلحات التي تُكتب بالحروف اللاتينية حتى في الإجابة العربية

| الاختصار | الاسم الكامل بالإنجليزية | المعنى بالعربية | الدرس |
|---|---|---|---|
| **`HTTPS`** | HyperText Transfer Protocol Secure | بروتوكول نقل النص الفائق الآمن (يضيف تشفير `TLS` إلى `HTTP`) | `2-1` / `3-2` |
| **`TLS`** | Transport Layer Security | بروتوكول أمان طبقة النقل المسؤول عن التشفير والمصافحة الآمنة | `2-1` |
| **`CA`** | Certificate Authority | سلطة إصدار الشهادات الرقمية الموثوقة | `2-1` |
| **`MFA` / `2FA`** | Multi-Factor / Two-Factor Authentication | المصادقة متعددة العوامل / الثنائية | `2-1` |
| **`VPN`** | Virtual Private Network | الشبكة الخاصة الافتراضية (نفق مشفر عبر الإنترنت) | `2-2` |
| **`DMZ`** | Demilitarized Zone | المنطقة منزوعة السلاح لعزل الخوادم العامة عن الشبكة الداخلية | `2-2` |
| **`HTTP`** | HyperText Transfer Protocol | بروتوكول نقل النص الفائق لتبادل الطلبات والردود بين العميل والخادم | `3-2` |
| **`GET`** | GET Method | طريقة طلب لاسترجاع البيانات من الخادم (هات) | `3-2` |
| **`POST`** | POST Method | طريقة طلب لإرسال البيانات إلى الخادم (ابعت) | `3-2` |
| **`API`** | Application Programming Interface | واجهة برمجة التطبيقات لتبادل البيانات بين البرمجيات | `3-2` |
| **`JSON`** | JavaScript Object Notation | صيغة بيانات نصية منظمة وسهلة القراءة لتبادل البيانات عبر `API` | `3-2` |
| **`HTML`** | HyperText Markup Language | لغة توصيف تحدد **بنية وهيكل** صفحة الويب | `3-3` |
| **`CSS`** | Cascading Style Sheets | لغة تنسيق تحدد **مظهر وتصميم** صفحة الويب (الألوان، الخطوط، التخطيط) | `3-3` |
| **`SEO`** | Search Engine Optimization | تحسين محركات البحث لزيادة ظهور الصفحة وفهم بنيتها | `3-3` |
| **`UCD`** | User-Centered Design | التصميم المتمركز حول المستخدم | `4-2` |
| **`CRAP`** | Contrast, Repetition, Alignment, Proximity | مبادئ التصميم الأربعة: التباين، التكرار، المحاذاة، التقارب | `4-2` |
| **`PV`** | Page View | إجمالي عدد مرات مشاهدة الصفحة | `4-3` |
| **`CVR`** | Conversion Rate | معدل التحويل (نسبة الزيارات التي حققت الإجراء المستهدف) | `4-3` |
| **`PDCA`** | Plan – Do – Check – Act | دورة التحسين المستمر: خطّط ← نفّذ ← افحص ← تصرّف | `4-4` |
| **`XAI`** | Explainable Artificial Intelligence | الذكاء الاصطناعي القابل للتفسير | `1-4` |

## ثانيًا: جدول الفروق الحاسمة بين المصطلحات المتشابهة (مفتاح أسئلة الامتحان)

| المجموعة المتشابهة | الدرس | الفرق الحاسم في سطر واحد |
|---|---|---|
| **الواقع المعزز (`AR`) مقابل الواقع الافتراضي (`VR`)** | `1-1` | **`AR`** يضيف معلومات رقمية **فوق** العالم الحقيقي؛ بينما **`VR`** **يستبدل** العالم الحقيقي بفضاء افتراضي كامل. |
| **الحوسبة السحابية (`Cloud`) مقابل الحوسبة الطرفية (`Edge`)** | `1-1` | **السحابية** توفر الموارد كخدمة عبر الإنترنت لبيانات ضخمة؛ **الطرفية** تعالج البيانات **قريبًا من مصدرها** (كالسيارة ذاتية القيادة) لتقليل زمن الاستجابة. |
| **البت الكلاسيكي (`Bit`) مقابل الكيوبت (`Qubit`)** | `1-1` | **البت الكلاسيكي** يأخذ قيمة واحدة (`0` أو `1`)؛ **الكيوبت** يعتمد على **التراكب الكمي (`Quantum Superposition`)** لتمثيل الحالتين معًا لمعالجة فئات محددة من المسائل بسرعة فائقة. |
| **`AI` ⊃ `Machine Learning` ⊃ `Deep Learning` ⊃ `Generative AI`** | `1-2` | علاقة احتواء متداخلة: الذكاء الاصطناعي هو المجال الأوسع، بداخله التعلم الآلي، وبداخله التعلم العميق (شبكات عصبية متعددة الطبقات)، والذكاء التوليدي يعتمد على التعلم العميق لإنتاج محتوى جديد. |
| **مشكلة الصندوق الأسود (`Black-box`) مقابل `XAI`** | `1-3` / `1-4` | **الصندوق الأسود** هو المشكلة (عدم وضوح كيف وصل النظام لقراره)؛ و**`XAI`** هو الحل (تقنية توضح للبشر العوامل والأسباب وراء القرار). |
| **التحيز في البيانات (`Data Bias`) مقابل التحيز الخوارزمي (`Algorithmic Bias`)** | `1-4` | الأول انحياز أو نقص تمثيل في **بيانات التدريب** (السبب)، والثاني نمط غير عادل في **أحكام ومخرجات النظام** (النتيجة). |
| **المسؤولية (`Responsibility`) مقابل المساءلة (`Accountability`)** | `1-4` | **المسؤولية** تحدد أدوار وواجبات كل طرف (مطور، مشغل، مستخدم)؛ **المساءلة** تعني تحديد الجهة التي تُحاسب وتجيب عن قرارات النظام وآثاره. |
| **التشفير غير المتماثل (`Public-key`) مقابل التشفير المتماثل (`Common-key`)** | `2-1` | **غير المتماثل** (مفتاح عام + مفتاح خاص) بطيء ويُستخدم **لمشاركة المفتاح بأمان**؛ **المتماثل** (مفتاح واحد مشترك) سريع ويُستخدم **لتبادل كميات البيانات الكبيرة**. |
| **اتجاه المفاتيح في التشفير مقابل التوقيع الرقمي** | `2-1` | في **التشفير**: المفتاح **العام** يشفر والخاص يفك التشفير؛ في **التوقيع الرقمي**: المفتاح **الخاص** يوقّع والمفتاح **العام** يتحقق من التوقيع. |
| **التوقيع الرقمي (`Digital Signature`) مقابل الشهادة الرقمية (`Digital Certificate`)** | `2-1` | **التوقيع الرقمي** يثبت سلامة **البيانات** وهوية المرسل ويمنع الإنكار؛ **الشهادة الرقمية** (من `CA`) تثبت أصالة **الطرف/الموقع**. |
| **الجدار الناري (`Firewall`) مقابل `DMZ` مقابل انعدام الثقة (`Zero Trust`)** | `2-2` | **الجدار الناري** يفلتر عند البوابة؛ **`DMZ`** تعزل الخوادم العامة عن الشبكة الداخلية؛ **انعدام الثقة** لا يثق بأي اتصال حتى من داخل الشبكة ويتحقق في كل مرة. |
| **الاحتواء (`Containment`) مقابل الاستئصال (`Eradication`)** | `2-3` | **الاحتواء** عزل الأجهزة المصابة فورًا لمنع انتشار الضرر؛ **الاستئصال** إزالة السبب الجذري (كالبرمجية الخبيثة) قبل استعادة النظام. |
| **الواجهة الأمامية (`Frontend`) مقابل الخلفية (`Backend`) مقابل قاعدة البيانات (`Database`)** | `3-1` | **الأمامية** تعمل على المتصفح (الشاشة)؛ **الخلفية** تعمل على الخادم (التفكير والمعالجة)؛ **قاعدة البيانات** تخزن وتسترجع وتتعامل مع **الخلفية فقط**. |
| **`GET` مقابل `POST`** | `3-2` | **`GET`** لاسترجاع البيانات من الخادم (عرض صفحة/بحث)؛ **`POST`** لإرسال بيانات إلى الخادم (تسجيل دخول/إرسال نموذج). |
| **`HTTP` مقابل `API`** | `3-2` | **`HTTP`** هو بروتوكول النقل؛ **`API`** هو القواعد والواجهة التي تحدد شكل البيانات المتبادلة فوق البروتوكول. |
| **رموز الحالة `200` مقابل `404` مقابل `500`** | `3-2` | **`2xx` (`200`)** نجاح الطلب؛ **`4xx` (`404`)** خطأ من جهة العميل (الصفحة غير موجودة)؛ **`5xx` (`500`)** خطأ داخلي في الخادم. |
| **`HTML` مقابل `CSS` مقابل `JavaScript`** | `3-3` | **`HTML`** البنية والهيكل؛ **`CSS`** المظهر والألوان والتخطيط؛ **`JavaScript`** السلوك والتفاعل الديناميكي. |
| **التباين (`Contrast`) مقابل التقارب (`Proximity`)** | `4-2` | **التباين** إبراز العنصر الأهم بالاختلاف (حجم/لون)؛ **التقارب** وضع العناصر المترابطة قريبة من بعضها لتُقرأ كمجموعة واحدة. |
| **التقييم الكيفي (`Qualitative`) مقابل التقييم الكمي (`Quantitative`)** | `4-3` | **الكيفي** يجيب عن **«لماذا؟»** (مقابلات، اختبار قابلية الاستخدام، تقييم استدلالي)؛ **الكمي** يجيب عن **«كم/ما النسبة؟»** (`PV`, `Bounce Rate`, `CVR`, `A/B Testing`). |

## ثالثًا: مسرد مصطلحات الفصل الأول (تكنولوجيا المعلومات والمجتمع)

### الدرس `1-1`: تطور تكنولوجيا المعلومات والتحول الاجتماعي
| المصطلح بالعربية | المصطلح بالإنجليزية | التعريف الدقيق |
|---|---|---|
| **قانون مور** | `Moore's Law` | ملاحظة تجريبية تنص على أن عدد الترانزستورات في الدائرة المتكاملة يتضاعف كل عامين تقريبًا. |
| **شبكات التواصل الاجتماعي** | `SNS (Social Networking Service)` | منصات تتيح للمستخدمين التواصل ونشر المحتوى ومشاركته، وتتميز بالسرعة الفائقة في نشر المعلومات. |
| **التجارة الإلكترونية** | `E-commerce (EC)` | بيع وشراء السلع والخدمات عبر شبكة الإنترنت. |
| **العمل عن بُعد** | `Remote work` | أسلوب عمل يؤدي فيه الفرد مهامه من المنزل أو من مكان بعيد باستخدام الإنترنت وتقنيات الاتصال. |
| **التعلّم عبر الإنترنت** | `Online learning` | نمط تعليمي وتدريبي تُقدَّم فيه الدروس والمواد التعليمية عبر الإنترنت. |
| **الدفع غير النقدي** | `Cashless payment` | إجراء المدفوعات دون نقود ورقية باستخدام البطاقات أو المحافظ الإلكترونية أو رموز `QR`. |
| **الحوسبة السحابية** | `Cloud computing` | تقديم موارد تكنولوجيا المعلومات (خوادم، تخزين، برمجيات) كخدمة عبر الإنترنت. |
| **الحوسبة الطرفية** | `Edge computing` | معالجة البيانات بالقرب من مصدر توليدها (على الجهاز نفسه أو محليًا) بدلًا من إرسالها كلها للسحابة لتقليل زمن الاستجابة (`Latency`). |
| **القيادة الذاتية** | `Autonomous driving` | تقنية تستخدم الذكاء الاصطناعي والكاميرات والمستشعرات لإدراك المحيط وقيادة المركبة واتخاذ القرار الفوري. |
| **الواقع المعزّز** | `AR (Augmented Reality)` | تقنية تضيف معلومات أو عناصر رقمية فوق مشاهد العالم الحقيقي. |
| **الواقع الافتراضي** | `VR (Virtual Reality)` | تقنية تغمر المستخدم كليًا داخل بيئة افتراضية مولدة حاسوبيًا. |
| **الحوسبة الكمّية** | `Quantum computing` | نهج حوسبي يستخدم مبادئ ميكانيكا الكم (مثل التراكب الكمي والكيوبت `Qubit`) لحل فئات محددة من المسائل المعقدة بسرعة فائقة. |

### الدرس `1-2`: كيف يعمل الذكاء الاصطناعي
| المصطلح بالعربية | المصطلح بالإنجليزية | التعريف الدقيق |
|---|---|---|
| **الذكاء الاصطناعي** | `AI (Artificial Intelligence)` | المجال الواسع الذي يضم أنظمة حاسوبية تحاكي القدرات الذهنية البشرية مثل التعلم والاستدلال والتنبؤ والتعرف على الكلام والصور. |
| **الذكاء الاصطناعي ضيق النطاق** | `Narrow AI` | أنظمة مصممة لأداء مهمة محددة أو مجموعة محدودة من المهام (وهو السائد في معظم الأنظمة الحالية). |
| **التعلّم الآلي** | `Machine Learning (ML)` | فرع من الذكاء الاصطناعي تتعلم فيه النماذج أنماطًا من البيانات لإجراء تنبؤات أو تصنيفات دون برمجة كل قاعدة صراحةً. |
| **التعلّم العميق** | `Deep Learning (DL)` | أسلوب متقدم داخل التعلم الآلي يعتمد على شبكات عصبية متعددة الطبقات المخفية لتعلم تمثيلات وأنماط معقدة. |
| **الشبكة العصبية الاصطناعية** | `Artificial Neural Network` | نظام حاسوبي مستوحى بصورة مبسطة من ترابط الخلايا العصبية في الدماغ، يتكون من طبقة إدخال وطبقات مخفية وطبقة إخراج وتتغير أوزانه أثناء التدريب. |
| **الذكاء الاصطناعي التوليدي** | `Generative AI (GenAI)` | أنظمة ذكاء اصطناعي مبنية على التعلم العميق تُنشئ محتوى جديدًا (نصوص، صور، صوت، كود برمجي) بناءً على بيانات التدريب. |
| **الهلوسة** | `Hallucination` | ظاهرة ينتج فيها الذكاء الاصطناعي التوليدي مخرجات تبدو منطقية ومقنعة في صياغتها لكنها غير صحيحة واقعيًا. |

### الدرس `1-3`: الذكاء الاصطناعي في الحياة اليومية والصناعة
| المصطلح بالعربية | المصطلح بالإنجليزية | التعريف الدقيق |
|---|---|---|
| **نظام التوصية** | `Recommendation system` | نظام يتنبأ بتفضيلات المستخدم من بيانات سلوكه السابق ويعرض ترشيحات مناسبة (مثل يوتيوب وأمازون). |
| **المساعد الصوتي** | `Voice assistant` | نظام يتعرف على الكلام البشري ويفهم الأوامر الصوتية وينفذها (مثل `Siri` ومساعد جوجل). |
| **الترجمة الآلية** | `Machine translation` | خدمة تترجم النصوص والكلام تلقائيًا بين اللغات المختلفة. |
| **التعرّف على الوجه** | `Face recognition` | تقنية تكتشف وجوه الأشخاص في الصور أو الفيديو وتتعرف على هويتهم تلقائيًا. |
| **الذكاء الاصطناعي للتشخيص بالصور** | `Image-diagnosis AI` | تحليل الصور الطبية (كالأشعة السينية والتصوير المقطعي) لمساعدة الأطباء في الكشف المبكر عن الأمراض. |
| **الصيانة التنبؤية** | `Predictive maintenance` | تحليل بيانات المستشعرات في المصانع للتنبؤ بأعطال الآلات قبل وقوعها وجدولة صيانتها في الوقت المناسب. |
| **مشكلة الصندوق الأسود** | `Black-box problem` | عدم وضوح الكيفية أو المنطق الداخلي الذي توصل به نموذج الذكاء الاصطناعي المعقد إلى حكمه أو قراره. |

### الدرس `1-4`: القضايا الأخلاقية للذكاء الاصطناعي
| المصطلح بالعربية | المصطلح بالإنجليزية | التعريف الدقيق |
|---|---|---|
| **بيانات التدريب** | `Training data` | الأمثلة والبيانات التي يتعلم منها نظام الذكاء الاصطناعي أنماطه قبل تشغيله الفعلي. |
| **التحيّز الخوارزمي** | `Algorithmic bias` | نمط في مخرجات وأحكام الذكاء الاصطناعي يؤدي إلى نتائج غير عادلة أو تمييزية نتيجة تحيز البيانات أو التصميم. |
| **المتغير البديل** | `Proxy variable` | متغير يمثل بشكل غير مباشر سمة محمية (مثل العنوان الجغرافي كبديل غير مباشر للعِرق أو الدخل) فيُدخل التحيز خفيةً. |
| **الذكاء الاصطناعي القابل للتفسير** | `Explainable AI (XAI)` | تقنيات وأساليب تتيح للبشر فهم العوامل والأسباب التي أدت بالذكاء الاصطناعي إلى اتخاذ قرار معين (علاج الصندوق الأسود). |
| **العدالة** | `Fairness` | مبدأ أخلاقي يقتضي عدم التمييز ظلمًا ضد أي فرد أو فئة في أحكام النظام. |
| **الشفافية** | `Transparency` | إتاحة معلومات واضحة ومفهومة حول آلية عمل النظام وعملية اتخاذ القرار وحدوده. |
| **حماية الخصوصية** | `Privacy protection` | التعامل السليم مع البيانات الشخصية وحمايتها من الجمع غير المصرح به أو المراقبة المفرطة. |
| **المسؤولية** | `Responsibility` | تحديد أدوار وواجبات الأطراف المرتبطة بالنظام (المطور، الشركة المشغلة، المستخدم). |
| **المساءلة** | `Accountability` | تحديد الجهات المسؤولة عن قرارات النظام وآثاره وإمكانية محاسبتها ومطالبتها بالتفسير. |

## رابعًا: مسرد مصطلحات الفصل الثاني (الأمن السيبراني)

### الدرس `2-1`: تقنيات التشفير والمصادقة
| المصطلح بالعربية | المصطلح بالإنجليزية | التعريف الدقيق |
|---|---|---|
| **التشفير** | `Encryption` | تحويل البيانات إلى صيغة غير مقروءة لا يمكن فهمها إلا باستخدام مفتاح فك التشفير، لحماية السرية ومنع التنصت. |
| **`HTTPS`** | `HTTP Secure` | بروتوكول يضيف تشفير `TLS` إلى `HTTP` لتوفير ثلاث خدمات: التشفير، كشف التلاعب، والتحقق من هوية الخادم. |
| **مصافحة `TLS`** | `TLS handshake` | الإجراء التمهيدي لإنشاء اتصال آمن والتحقق من شهادة الخادم ومشاركة مفتاح الجلسة المتماثل. |
| **التشفير المتماثل** | `Symmetric / Common-key cryptography` | تشفير يستخدم مفتاحًا واحدًا مشتركًا للتشفير وفك التشفير؛ يمتاز بالسرعة العالية ويُستخدم لتبادل البيانات الكبيرة. |
| **التشفير غير المتماثل** | `Asymmetric / Public-key cryptography` | تشفير يستخدم زوجًا من المفاتيح (مفتاح عام للتشفير ومفتاح خاص لفك التشفير)؛ يُستخدم لمشاركة المفتاح المتماثل بأمان. |
| **المفتاح العام** | `Public key` | المفتاح المعلن المتاح لأي طرف لاستخدامه في تشفير البيانات المرسلة لصاحب المفتاح أو للتحقق من توقيعه الرقمي. |
| **المفتاح الخاص** | `Private key` | المفتاح السري المحفوظ لدى صاحبه فقط، ويُستخدم لفك تشفير ما شُفِّر بالمفتاح العام أو لإنشاء التوقيع الرقمي. |
| **التوقيع الرقمي** | `Digital signature` | تقنية تستخدم المفتاح الخاص للمرسل لتوقيع البيانات، فتكشف أي تلاعب بها وتثبت هوية المرسل وتحقق عدم الإنكار. |
| **عدم الإنكار** | `Non-repudiation` | ضمان عدم قدرة المرسل لاحقًا على إنكار إرساله للبيانات الموقعة رقميًا. |
| **الشهادة الرقمية** | `Digital certificate` | وثيقة إلكترونية تثبت أصالة الموقع أو الخادم وارتباط المفتاح العام بهويته الحقيقية. |
| **سلطة إصدار الشهادات** | `Certificate Authority (CA)` | جهة ثالثة موثوقة تصدر الشهادات الرقمية وتصادق على هوية المواقع والخوادم. |
| **المصادقة متعددة العوامل** | `Multi-Factor Authentication (MFA)` | التحقق من هوية المستخدم بالجمع بين عاملين أو أكثر من فئات مختلفة: **المعرفة** (`Knowledge`)، **الحيازة** (`Possession`)، **السمات البيومترية** (`Biometric`). |

### الدرس `2-2`: تصميم أمن الشبكات
| المصطلح بالعربية | المصطلح بالإنجليزية | التعريف الدقيق |
|---|---|---|
| **الجدار الناري** | `Firewall` | نظام يوضع عند نقطة دخول وخروج الشبكة ليسمح بمرور الاتصالات أو يمنعها وفق قواعد محددة مسبقًا. |
| **الشبكة الخاصة الافتراضية** | `VPN (Virtual Private Network)` | تقنية تنشئ نفقًا افتراضيًا مشفرًا فوق شبكة الإنترنت العامة لتأمين مسار الاتصال عن بُعد. |
| **المنطقة منزوعة السلاح** | `DMZ (Demilitarized Zone)` | منطقة شبكية معزولة توضع فيها الخوادم المكشوفة للخارج (كخادم الويب والبريد) لحماية الشبكة الداخلية في حال اختراقها. |
| **الدفاع في العمق** | `Defense in depth` | استراتيجية أمنية تقوم على وضع عدة طبقات حماية متتالية بحيث إذا اختُرقت طبقة، تتولى الطبقة التالية الحماية. |
| **انعدام الثقة** | `Zero trust` | نموذج أمني يفترض عدم الثقة في أي اتصال سواء من خارج الشبكة أو من داخلها، ويتحقق من الهوية والصلاحيات في كل طلب وصول. |
| **المحيط الأمني** | `Perimeter` | الحدود الفاصلة بين الشبكة الداخلية للمؤسسة والشبكة الخارجية. |
| **نقاط النهاية** | `Endpoints` | الأجهزة الطرفية المتصلة بالشبكة مثل الحواسيب المحمولة والهواتف الذكية والخوادم. |

### الدرس `2-3`: الاستجابة للحوادث وإدارة المخاطر
| المصطلح بالعربية | المصطلح بالإنجليزية | التعريف الدقيق |
|---|---|---|
| **الحادث الأمني** | `Security incident` | واقعة يحدث فيها ضرر فعلي لأمن المعلومات (مثل تسريب البيانات أو التلاعب بها أو توقف الخدمة). |
| **تسريب المعلومات** | `Information leak` | خروج بيانات سرية أو شخصية إلى أطراف غير مصرح لها. |
| **التلاعب بالبيانات** | `Data tampering` | تعديل أو حذف البيانات داخل النظام دون تصريح. |
| **توقف الخدمة** | `Service outage` | تعذر وصول المستخدمين إلى الخدمة نتيجة هجوم سيبراني (مثل هجمات حجب الخدمة) أو عطل أمني. |
| **الاستعداد** | `Preparation` | المرحلة الأولى (قبل وقوع الحادث): إعداد خطط وإجراءات وفرق الاستجابة مسبقًا. |
| **الاكتشاف** | `Detection` | المرحلة الثانية: رصد الحادث الأمني وتأكيد وقوعه. |
| **الاحتواء** | `Containment` | المرحلة الثالثة: عزل الأنظمة المصابة فورًا للحد من نطاق الضرر ومنع انتشاره. |
| **الاستئصال** | `Eradication` | المرحلة الرابعة: إزالة السبب الجذري للحادث (مثل حذف البرمجية الخبيثة وإغلاق الثغرة). |
| **التعافي** | `Recovery` | المرحلة الخامسة: استعادة الأنظمة والبيانات وإعادتها للعمل الطبيعي بأمان. |
| **منع التكرار** | `Prevention of recurrence` | المرحلة السادسة: تحليل أسباب الحادث واتخاذ إجراءات وقائية لمنع تكرره مستقبلًا. |
| **الأثر** | `Impact` | حجم الخسارة أو الضرر الناتج إذا وقع الخطر. |
| **الاحتمالية** | `Likelihood` | مدى احتمال وقوع الخطر، ويُحسب **حجم الخطر = الأثر × الاحتمالية**. |

## خامسًا: مسرد مصطلحات الفصل الثالث (تطبيقات الويب)

### الدرس `3-1`: البنية العامة لتطبيقات الويب
| المصطلح بالعربية | المصطلح بالإنجليزية | التعريف الدقيق |
|---|---|---|
| **تطبيق الويب** | `Web application` | برنامج يُستخدم مباشرة عبر متصفح الويب دون الحاجة إلى تنصيب برنامج مخصص على الجهاز. |
| **الواجهة الأمامية** | `Frontend` | الطبقة التي يراها المستخدم ويتفاعل معها مباشرة، وتعمل داخل **المتصفح (`Browser`)**. |
| **الواجهة الخلفية** | `Backend` | الطبقة المسؤولة عن منطق العمل ومعالجة البيانات واتخاذ القرارات، وتعمل على **الخادم (`Server`)**. |
| **قاعدة البيانات** | `Database` | النظام الذي ينظم البيانات ويخزنها ويديرها ويسترجعها، ويتواصل مباشرة مع **الواجهة الخلفية فقط**. |
| **البنية ثلاثية الطبقات** | `Three-tier architecture` | المعمارية القياسية لتطبيقات الويب المكونة من: الواجهة الأمامية + الواجهة الخلفية + قاعدة البيانات. |

### الدرس `3-2`: طرق الاتصال في تطبيقات الويب
| المصطلح بالعربية | المصطلح بالإنجليزية | التعريف الدقيق |
|---|---|---|
| **العميل** | `Client` | الطرف الذي يرسل الطلب (`Request`) لطلب بيانات أو معالجة (مثل المتصفح أو تطبيق الهاتف). |
| **الخادم** | `Server` | الطرف الذي يستقبل طلبات العميل ويعالجها ويعيد الرد (`Response`). |
| **`HTTP`** | `HyperText Transfer Protocol` | بروتوكول الاتصال الأساسي لتبادل الطلبات والردود بين العميل والخادم على الويب. |
| **طريقة `GET`** | `GET method` | طلب HTTP يُستخدم **لاسترجاع البيانات** من الخادم (مثل فتح صفحة أو جلب نتائج بحث). |
| **طريقة `POST`** | `POST method` | طلب HTTP يُستخدم **لإرسال بيانات** إلى الخادم لمعالجتها أو حفظها (مثل تسجيل الدخول أو إرسال نموذج). |
| **رمز الحالة** | `Status code` | رقم من 3 خانات في رد الخادم يوضح نتيجة الطلب: `200` (نجاح)، `404` (الصفحة غير موجودة — خطأ عميل)، `500` (خطأ داخلي في الخادم). |
| **واجهة برمجة التطبيقات** | `API` | آلية وقواعد تسمح لبرمجيات وتطبيقات مختلفة بتبادل البيانات والوظائف فيما بينها. |
| **`JSON`** | `JavaScript Object Notation` | صيغة بيانات نصية خفيفة ومنظمة على شكل أزواج (`مفتاح: قيمة`) تُستخدم على نطاق واسع في ردود `API`. |

### الدرس `3-3`: أساسيات تكنولوجيا الواجهة الأمامية
| المصطلح بالعربية | المصطلح بالإنجليزية | التعريف الدقيق |
|---|---|---|
| **`HTML`** | `HyperText Markup Language` | اللغة التي تحدد **بنية وهيكل** صفحة الويب (العناوين، الفقرات، الصور، الروابط). |
| **`CSS`** | `Cascading Style Sheets` | اللغة التي تحدد **مظهر وتنسيق** الصفحة (الألوان، الخطوط، الأحجام، التخطيط). |
| **`JavaScript`** | `JavaScript` | لغة البرمجة التي تضيف **السلوك والتفاعلية** للصفحة (الاستجابة للأزرار، تحديث جزء من الشاشة دون إعادة تحميلها). |
| **`HTML` الدلالي** | `Semantic HTML` | استخدام وسوم تدل على **معنى ودور** كل جزء في الصفحة مثل `<header>`, `<nav>`, `<main>`, `<footer>`. |
| **إمكانية الوصول** | `Accessibility` | تصميم المواقع بحيث يتمكن الجميع من استخدامها بمن فيهم ذوو الإعاقة البصرية عبر قارئات الشاشة (`Screen Readers`). |
| **تحسين محركات البحث** | `SEO` | تهيئة الصفحة وبنيتها الدلالية لكي تفهمها محركات البحث وتفهرسها بفعالية. |
| **التصميم المتجاوب** | `Responsive design` | تصميم يتكيف فيه تخطيط الصفحة وعناصرها تلقائيًا مع حجم شاشة الجهاز (حاسوب، جهاز لوحي، هاتف ذكي). |
| **إطار العمل** | `Framework` | مجموعة مكونات ووظائف برمجية جاهزة مبنية فوق اللغات الأساسية لتسريع تطوير التطبيقات وتنظيم الكود. |

## سادسًا: مسرد مصطلحات الفصل الرابع (تصميم الويب والوسائط)

### الدرس `4-1`: أنواع الوسائط وخصائصها
| المصطلح بالعربية | المصطلح بالإنجليزية | التعريف الدقيق |
|---|---|---|
| **الوسيط الإعلامي** | `Medium` | الوسيلة الناقلة للمعلومات (التلفزيون، الراديو، الصحف الورقية، المواقع الإلكترونية، شبكات التواصل الاجتماعي). |
| **اتصال أحادي الاتجاه** | `One-way communication` | تدفق المعلومات من المرسل إلى المستقبل فقط دون إمكانية رد مباشر (مثل التلفزيون، الراديو، الصحف). |
| **اتصال ثنائي الاتجاه** | `Two-way communication` | اتصال تفاعلي يتيح للمستقبل الرد والتعليق والمشاركة (مثل شبكات التواصل الاجتماعي، والمواقع عبر النماذج والتعليقات). |
| **الجمهور المستهدف** | `Target audience` | الفئة المحددة من الناس التي يُراد إيصال الرسالة أو الخدمة إليها. |
| **المدى / الانتشار** | `Reach` | حجم الجمهور الذي يستطيع الوسيط الوصول إليه. |

### الدرس `4-2`: تصميم المعلومات وتجربة المستخدم للمواقع
| المصطلح بالعربية | المصطلح بالإنجليزية | التعريف الدقيق |
|---|---|---|
| **التصميم المتمركز حول المستخدم** | `User-Centered Design (UCD)` | منهجية تصميم تنطلق من احتياجات المستخدم وموقف استخدامه الفعلي، لا من تفضيلات صاحب الموقع. |
| **البيرسونا** | `Persona` | نموذج لشخصية مستخدم متوقع ومحدد بسمات ملموسة (العمر، المهنة، الهدف، التحديات، سياق الاستخدام) لتوجيه التصميم. |
| **الإطار السلكي** | `Wireframe` | مخطط تخطيطي أولي للصفحة **بدون ألوان أو زخرفة** لتحديد أماكن المعلومات وأولوياتها قبل النقاش البصري. |
| **التباين** | `Contrast` | إبراز العناصر الأهم وتوضيح أولوية المعلومات عبر الاختلاف الواضح في الحجم أو اللون أو الوزن. |
| **التكرار** | `Repetition` | توحيد وتكرار الأنماط البصرية (الألوان، الخطوط، الأيقونات) عبر الصفحات لتحقيق الاتساق ومنع تشتت المستخدم. |
| **المحاذاة** | `Alignment` | ترتيب العناصر على خط أساس مشترك لتحقيق النظام والوضوح البصري. |
| **التقارب** | `Proximity` | وضع العناصر المترابطة قريبة من بعضها لتُدرَك كمجموعة واحدة بنظرة سريعة. |
| **قابلية الاستخدام** | `Usability` | مدى سهولة وفعالية استخدام الموقع لتحقيق هدف المستخدم دون تعقيد. |

### الدرس `4-3`: أساليب تقييم المواقع الإلكترونية
| المصطلح بالعربية | المصطلح بالإنجليزية | التعريف الدقيق |
|---|---|---|
| **التقييم الكيفي** | `Qualitative evaluation` | تقييم يكتشف **«لماذا؟»** يتصرف المستخدمون بطريقة معينة عبر ملاحظة سلوكهم وسماع آرائهم (لا يُقاس بالأرقام). |
| **التقييم الكمّي** | `Quantitative evaluation` | تقييم يقيس **«كم / ما النسبة؟»** باستخدام البيانات الرقمية وإحصاءات الزيارات. |
| **اختبار قابلية الاستخدام** | `Usability testing` | أسلوب كيفي يقوم على ملاحظة مستخدمين حقيقيين أثناء تنفيذ مهام فعلية على الموقع لاكتشاف نقاط الصعوبة. |
| **المقابلات** | `Interviews` | أسلوب كيفي لسماع آراء المستخدمين مباشرة وفهم احتياجاتهم وأسباب عدم رضاهم. |
| **التقييم الاستدلالي** | `Heuristic evaluation` | أسلوب كيفي يفحص فيه خبراء واجهة الموقع استنادًا إلى مبادئ وقواعد خبرة معروفة دون الحاجة لمستخدمين. |
| **تحليلات الويب** | `Web analytics` | الأسلوب الكمي المركزي لجمع وتحليل بيانات استخدام الموقع رقميًا. |
| **مرات مشاهدة الصفحة** | `Page View (PV)` | إجمالي عدد مرات عرض الصفحة، ويقيس حجم الظهور والانتشار. |
| **معدل الارتداد** | `Bounce rate` | نسبة الزيارات التي يغادر فيها الزائر الموقع بعد مشاهدة صفحة واحدة فقط دون تفاعل إضافي. |
| **معدل التحويل** | `Conversion Rate (CVR)` | نسبة الزيارات التي انتهت بتحقيق الهدف المطلوب (شراء، تسجيل، اشتراك)، وهو المؤشر الأهم لنتائج الأعمال. |
| **اختبار `A/B`** | `A/B testing` | أسلوب كمي يقارن بين نسختين (`A` و`B`) بعرضهما على المستخدمين لتحديد أيهما يحقق نتائج أفضل بالبيانات. |

### الدرس `4-4`: عملية التحسين التكراري للمواقع
| المصطلح بالعربية | المصطلح بالإنجليزية | التعريف الدقيق |
|---|---|---|
| **دورة `PDCA`** | `PDCA cycle` | إطار للتحسين المستمر يتكون من 4 مراحل متكررة: **خطّط (`Plan`) ← نفّذ (`Do`) ← افحص (`Check`) ← تصرّف (`Act`)**. |
| **التحسين المستمر** | `Continuous improvement` | تطوير الموقع تدريجيًا عبر دورات متتالية بناءً على بيانات الاستخدام الفعلي بدلًا من التوقف عند الإطلاق الأول. |
| **التفكير التصميمي** | `Design thinking` | منهجية لاكتشاف المشكلات وتوليد الحلول من منظور المستخدم عبر 5 خطوات: **التعاطف (`Empathize`) ← التحديد (`Define`) ← توليد الأفكار (`Ideate`) ← النموذج الأولي (`Prototype`) ← الاختبار (`Test`)**. |
| **النموذج الأولي** | `Prototype` | نموذج تجريبي سريع يُبنى لاختبار الأفكار مع المستخدمين وجمع التغذية الراجعة قبل البناء النهائي. |
